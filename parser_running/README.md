# Парсер беговых протоколов

Источники → SQLite (`data/running.db`). Целевая схема БД и правила — [docs/parser-db-spec.md](../docs/parser-db-spec.md).
Разведка площадок — [SOURCES.md](SOURCES.md), журнал ошибок — [ERRORS.md](ERRORS.md) (E1–E35).

## Запуск
```bash
pip install requests beautifulsoup4 lxml
python seed_journal.py                              # журнал ERRORS.md → очередь issue + known_exception
python run.py --source russiarunning --events 40   # также: timerman, runc, grom
python run.py --source russiarunning --events 300 --sber-only   # RR: протоколы только там, где в клубах есть Сбер
python dedup.py                                     # дедупликация стартов и результатов
python recon_blocked.py                             # разведка гео-заблокированных площадок (запускать из РФ)
```
Ответы площадок кешируются в `data/raw/<площадка>/`, повторный прогон идёт без сети и ничего не задваивает.
`data/` в git не попадает (персональные данные).

> Часть площадок не открывается с некоторых зарубежных IP (E1, E19). Запускать из российской сети.

### Очередь проблем (`issue`)
Вместо простого журнала ошибок — очередь, которую будет разбирать агент или человек:
- одна проблема — одна строка (`fingerprint`), повторы считаются в `occurrences`, закрытая проблема при повторе открывается снова;
- статусы: `new` → `agent_working` → `proposed` → `approved` / `rejected` → `resolved`, а также `known` и `blocked`;
- исполнитель: `agent` (форматы и правила разбора), `human` (решение заказчика), `infra` (сеть, блокировки);
- `known_exception` — особенности данных, которые чинить не надо (сейчас: спринты с финалом, E28);
- журнал E1–E35 перенесён в очередь как история (`seed_journal.py`): 19 закрыто, 12 ждут решения, 2 известные особенности, 1 заблокирована сетью.

### Дедупликация (`dedup.py`)
- **Старты:** 2 дубля (Казанский и Альметьевский полумарафоны: russiarunning ↔ timerman).
- **Результаты:** склеено 9 670. Оценка по эталону `participantId` RR: **precision 100%, recall 99,98%** (9670 из 9672).
  Это оценка склейки **зеркал одного старта** (тот же протокол на двух сайтах платформы RR). `participantId` привязан к старту и между разными стартами не повторяется (E34), поэтому для сопоставления атлетов между стартами нужен ручной эталон.
- **Между разными платформами** (runc, grom, RR): из 25 пар стартов одного дня все — действительно разные старты, ложных склеек 0. Совпадающего старта на разных платформах в выборке не было, поэтому полнота этого пути ещё не проверена.

## Проверки качества на каждой дистанции
1. Записей столько, сколько заявляет площадка (где она это сообщает).
2. Пол известен (анонимные строки без ФИО не считаются, E26).
3. У всех финишёров есть официальное время.
4. Места идут по порядку.
5. Время растёт с местом — по тому времени (чистое/грязное), по которому площадка ставит места (`place_by`).
6. Все статусы из набора FIN / DNF / DSQ / DNS / NC / LAP.

## Модули
| Файл | Что делает |
|---|---|
| `rr_platform.py` | Клиент и коннектор платформы RussiaRunning (russiarunning, timerman; те же эндпоинты у лыжных legkovrace, pionercup) |
| `runc.py` | Коннектор results.runc.run (HTML, два вида страниц: личное и общее время) |
| `grom.py` | Коннектор grom.place (JSON из атрибута `:initial-rows`, колонки ищутся по названию) |
| `http_cache.py` | GET с кешем на диске, ретраи с нарастающей паузой, починка кодировки |
| `normalize.py` | Время; дистанция из названия (км, мили, метры) → зачётный норматив (±2%); даты на русском; пол; статусы; `place_by` по данным; детектор клуба Сбера |
| `store.py` | Общая запись в БД (upsert) и проверки 1–6 |
| `db.py` | Таблицы `source`, `event`, `race`, `result`, `issue`, `known_exception` + колонки дедупа и `club_source`; `report_issue()` |
| `seed_journal.py` | Перенос журнала ERRORS.md в очередь `issue` и стартовые `known_exception` |
| `evals/` | Протокол агента-ремонтника, проверяющий модуль и тест-кейсы (см. [evals/README.md](evals/README.md); спека агента — [docs/agent-spec.md](../docs/agent-spec.md), путеводитель — [docs/agent-guide.md](../docs/agent-guide.md)) |
| `run.py` | Общий прогон для всех площадок, отчёт `data/report_<площадка>.json` |
| `dedup.py` | Дедуп стартов и результатов, отчёт `data/report_dedup.json` |
| `recon_blocked.py` | Разведка площадок, недоступных с зарубежных IP |
