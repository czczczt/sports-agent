# Агент-ремонтник на GigaChat

Реализация роли «Ремонтник» из [agent-spec.md](../../../docs/agent-spec.md): получает задачу из очереди проблем
парсера и предлагает решение — правку кода (`patch`), известное исключение (`known_exception`) или передачу
людям (`escalate`). Сам ничего не применяет: применяют проверяющий модуль и человек.

| Файл | Что делает |
|---|---|
| `gigachat_agent.py` | `solve(task, sandbox, tools)` — цикл агента, промпт, разбор ответа модели, самопроверки |
| `gigachat_client.py` | Клиент GigaChat: ключ из `.env`, токен доступа, повторы, кеш ответов |

## Запуск

```powershell
pip install requests beautifulsoup4 lxml "psycopg[binary]"
cd parser_running\evals
$env:PYTHONUTF8 = "1"          # только Windows: иначе run_evals падает на кодировке
python agents\gigachat_client.py          # проверить ключ
python run_evals.py --agent gigachat_agent
```

`.env` в корне репозитория (в git не попадает):
```env
GIGACHAT_CREDENTIALS=<ключ авторизации из личного кабинета>
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2-Max
# GIGACHAT_CA_BUNDLE=<путь к сертификату НУЦ Минцифры>   правильный вариант
# GIGACHAT_VERIFY_SSL=false                              только для отладки
# GIGACHAT_CACHE=0                                       не использовать кеш ответов
```

## Как работает

1. Проблема сети (`stage = fetch`) → сразу `escalate:infra`, модель не вызывается.
2. `tools.run_checks([])` — воспроизвести проблему: какие проверки падают и что получилось.
3. Модели отправляется: задача, результат проверок, код коннектора площадки и `normalize.py`
   **с номерами строк**, функция `checks()` из `store.py` (только для чтения), сохранённая страница площадки.
4. Модель отвечает в текстовом формате: действие, обоснование и, для правки, «замени строки с–по этим кодом».
5. Агент проверяет ответ, а не верит ему:
   - правка → точный фрагмент `old` агент вырезает из файла сам и прогоняет `run_checks` (задача + регрессия);
   - известное исключение → шаблон должен ловить задачу, ловить такой же случай на другом старте
     и не ловить другие дистанции и проверки.
6. Не прошло → модель получает, что именно не так; всего до 4 попыток.
7. Не получилось → `escalate:human` с диагнозом. Ложная починка хуже честной передачи.

Решения и почему:

| Решение | Почему |
|---|---|
| Свой цикл, без LangGraph и function calling | Спека §10 допускает; цикл фиксированный, LLM-планировщик не нужен; с GigaChat надёжнее |
| Файлы кладутся в запрос, а не запрашиваются моделью (`list_files`/`read_file` из §6) | Нужные файлы известны заранее по площадке задачи; меньше шагов и ошибок |
| Правки номерами строк, а не копией кода | Модель не может скопировать фрагмент символ в символ (теряет `:`, отступы) — это была главная причина провалов |
| Ответ текстом, а не JSON | Код внутри JSON модель экранирует с ошибками |
| Кеш ответов в `parser_running/data/llm_cache/` | Повторный прогон не тратит токены и не требует сети; ключ кеша включает модель и промпт |

Журнал рассуждений по каждой задаче: `parser_running/data/agent_traces/<id>.md`
(что агент видел, ответы модели, результаты проверок, итог).

## Результаты на стенде evals (2026-10-29)

| Агент | Решено | Нарушения безопасности | Регрессии и ложные починки | Неверные эскалации |
|---|---|---|---|---|
| `template` (без модели) | 2 / 8 | 0 | 0 | 0 |
| GigaChat-2-Pro | 3 / 8 | 0 | 0 | 0 |
| **GigaChat-2-Max** | **6 / 8** | **0** | **0** | **0** |

GigaChat-2-Max: до ~25 с и ~5–23 тыс. токенов на задачу, ~90 тыс. токенов на весь прогон.

Не решены:
- **E24** (grom, место «-1/-1»): причину нашёл, но поставил статус `DNF` вместо `NC` — модель не знает
  смысла кодов статусов. Передано человеку.
- **E32** (дистанции «100 м», «1 миля»): правильная идея, но в регулярном выражении латинская `m`
  вместо кириллической `м`. Передано человеку.

Важно: промпт дважды правился по результатам на этих же 8 кейсах, поэтому 6/8 — оптимистичная оценка.
Реальное качество покажут новые кейсы из очереди `issue`.
