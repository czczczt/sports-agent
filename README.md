## 1. Архитектура и стек технологий

### 1.1 Сквозной конвейер данных (Data Pipeline)

Архитектура системы построена по модульному принципу со строгим разделением ответственности:

```
[Источники] ──> [Сбор (L1 / L2)] ──> [Raw-кэш] ──> [Нормализация] ──> [Валидация] ──> [Матчинг атлетов] ──> [Расчет баллов] ──> [Рейтинг и UI]
```

1. **Реестр источников:** Конфигурация сайтов, типов соревнований и стратегий доступа.
2. **Сбор (L1/L2):** 
   - **L1 (HTTP/API):** Прямые HTTP-запросы (`httpx`, `requests`) к закрытым и публичным JSON API площадок, либо парсинг серверного HTML (`BeautifulSoup4`, `lxml`).
   - **L2 (Headless Browser / MCP):** Сбор страниц со сложным SPA-рендерингом (`Playwright`) в качестве резервного пути самовосстановления.
3. **Raw-слой (Кэш на диске и в БД):** Сохранение неизмененных исходных страниц и ответов API с контролем `content_hash` (SHA-256). Обеспечивает возможность повторного прогона без сетевой нагрузки и траты токенов.
4. **Нормализация:** Приведение данных к каноническому виду: миллисекунды времени, нормализованные дистанции, валидные статусы финиша, чистка ФИО, распознавание принадлежности к клубу.
5. **Валидация данных:** Автоматический аудит протоколов по 6 математическим инвариантам до сохранения в БД.
6. **Матчинг и дедупликация:** Сопоставление строк протоколов с профилями реальных людей, склейка зеркал одного старта, выявление сотрудников Сбера.
7. **Рейтинговый движок:** Чистые детерминированные функции расчета очков относительно нормативов 2026 года и сохранение рейтинговой таблицы со скользящим окном 365 дней.
8. **Интерфейс и ИИ-анализ:** Веб-витрина на FastAPI, карточки спортсменов, соревновательные квантили пелотона и персональные резюме от GigaChat.

### 1.2 Технологический стек

* **Бэкенд:** Python 3.12 / 3.14, FastAPI, Starlette, Uvicorn, Pydantic v2.
* **База данных:** SQLite 3 в режиме высокой производительности (`PRAGMA journal_mode=WAL; PRAGMA busy_timeout=20000; PRAGMA synchronous=NORMAL;`). Поддерживаются оконные функции `ROW_NUMBER() OVER (...)`. Схемы таблиц также совместимы с PostgreSQL (`docker-compose.yaml`).
* **Фронтенд:** Серверный рендеринг Jinja2, ванильный JavaScript (ES6+), CSS с кастомной дизайн-системой токенов (`theme.css`), шрифты Unbounded и Golos Text, Chart.js 4.4.1 (графики динамики темпа и гистограммы распределения), Air Datepicker 3.5.3 (выбор дат).
* **Сбор и парсинг:** `requests`, `httpx`, `beautifulsoup4`, `pdfplumber`, `pillow`, `pytesseract` (Tesseract OCR 5).
* **ИИ и LLM-стек:** GigaChat API (модели `GigaChat-2-Pro`, `GigaChat-Pro`), SDK `gigachat`, Model Context Protocol (MCP) orchestrator, автономный агент исправления парсеров (`parse_url.py`).

### 3.2 Автоматические проверки качества данных (6 инвариантов)

Каждая загруженная дистанция перед сохранением в базу проходит валидатор (`parser_running/store.py`):
1. **Полнота выборки:** Число сохранённых записей совпадает с числом, заявленным организатором в заголовке протокола.
2. **Определённость пола:** Пол участников валиден (`M`/`F`). Анонимные записи без ФИО («N.N.») отсеиваются.
3. **Наличие результата:** У всех участников со статусом `FIN` присутствует официальное время финиша.
4. **Непрерывность мест:** Места финишеров строго идут по порядку, начиная с 1, без пропусков.
5. **Монотонность времени:** Время финиша не убывает с ростом места. Сравнение производится по тому времени (чистому или пистолетному), по которому площадка рассчитывала места (`race.place_by`).
6. **Контроль статусов:** Записи имеют валидный спортивный статус: `FIN` (финиш), `DNF` (сошёл), `DNS` (не стартовал), `DSQ` (дисквалификация), `NC` (вне зачёта), `LAP` (снят на круг).

### 3.3 Очередь проблем (`issue`)

Для фиксации сбоев и работы ИИ-агента ремонта используется таблица `issue`:
* Уникальный хэш инцидента (`fingerprint`) предотвращает дублирование записей об одной и той же проблеме, инкрементируя счётчик `occurrences`.
* Статусы жизненного цикла: `new` $\to$ `agent_working` $\to$ `proposed` $\to$ `approved` / `rejected` $\to$ `resolved`.
* Таблица `known_exception` изолирует особенности регламента, не являющиеся багами (например, стадионные спринты с финалами).

## 4. Модуль сбора биатлонных протоколов (`parser_biathlon`)

### 4.1 Источники и обработка

1. **`biathlonrus.com` (Союз биатлонистов России):** Официальный календарь соревнований (Чемпионат России, Кубок России, Первенства). Протоколы публикуются в формате PDF (хронометраж WSRP, Ski123, SIWIDATA).
2. **`base.biathlonrus.com`:** Реестр спортсменов СБР (4 569 атлетов в CSV) — эталон для верификации участников и разрешения коллизий OCR.

### 4.2 Технология гибридного распознавания (PDF + OCR)

* **Поколоночный парсинг (`parser_biathlon/parse_protocol.py`):** Извлечение текстового слоя через `pdfplumber` с привязкой к колонкам времени финиша.
* **OCR растровых ячеек (`parser_biathlon/ocr_names.py`):** При отсутствии текстового слоя ФИО фрагмент ячейки рендерится в 400 DPI и распознаётся через Tesseract 5 (языковой пакет `rus`, `--psm 7`).
* **Точность решения (`parser_biathlon/eval_ocr.py`):** Точность извлечения фамилии и имени составляет **100.0%**, отчества — **98.6%**, общий посимвольный уровень ошибок (CER) — всего **0.17%**.

```
POST   /api/agent-review/{id}/decide — Подтверждение / отклонение решения агента (approve / reject)

```

## 7. ИИ-агенты и контур самовосстановления (GigaChat + MCP)

### 7.1 Агент персональной оценки спортсмена

Система строго разделяет детерминированную математику и языковую модель:
1. **Детерминированный слой (`app/services/analytics_service.py`):**
   * **Соревновательный процентиль:**
     $$\text{Percentile} = \frac{N_{\text{участников}} - \text{Place} + 1}{N_{\text{участников}}} \times 100\%$$
   * **Относительный прогресс PB:** процент изменения темпа между первым и лучшим забегом на каждой дистанции.
   * **Коэффициент вариации темпа (стабильность):**
     $$CV = \frac{\sigma}{\mu} \times 100\%$$
2. **Генеративный слой (`app/services/agent_service.py`):**
   Компактный JSON с вычисленными метриками передаётся в **GigaChat API**. Модель формирует персональное структурированное резюме: сильные стороны, динамика, рекомендации по тренировкам и стартам.
3. **Локальный Fallback:**
   При отсутствии API-ключа GigaChat приложение автоматически генерирует качественный аналитический отчёт силами локального экспертного модуля без прерывания работы сервиса.
4. **Кэширование в БД:**
   Сгенерированный отчёт сохраняется в таблице `athlete_assessment_cache`. Повторные открытия профиля не расходуют токены и отображаются мгновенно.

### 7.2 Контур самовосстановления парсеров и утилита `parse_url.py`

* **CLI-генератор парсеров (`parse_url.py`):**
  Автономный скрипт, принимающий URL протокола соревнования (например, `https://probeg.org/race/129181/`). Загружает HTML, извлекает фрагмент таблицы, формирует промпт для модели **`GigaChat-2-Pro`**, генерирует чистый код коннектора на BeautifulSoup и сохраняет тестовый скрипт проверки (`test_probeg_parser.py`).
* **Оркестратор MCP (`app/mcp_agent/`):**
  * `validator.py`: аудит входящих данных на аномалии (доля `NULL`, нарушение монотонности мест).
  * `orchestrator.py`: регистрация инцидента в очереди `issue` со статусом `agent_working`.
  * `mcp_client.py`: вызов инструментов Playwright MCP (`playwright_fetch_page`, `llm_extract_table`, `analyze_network`).
* **Веб-панель проверки (`/agent-review`):**
  Предоставляет человеку возможность в один клик утвердить или отклонить патч, запустить повторную генерацию или удалить задачу с автоматической очисткой диска.

## 8. Рейтинговый движок и методика расчета баллов

Все модули расчёта спроектированы как чистые детерминированные функции `(результат, контекст) -> (баллы, расшифровка)` и покрыты тестами (`tests/test_scoring.py`, `tests/test_scoring_db.py`, `tests/test_distance_scoring.py`).

### 8.1 Бег (шоссе и стадион)

Баллы начисляются относительно официальных нормативов на 2026 год (`parser_running/scoring.py`):
$$\text{Баллы} = \frac{\text{Норматив (сек)}}{\text{Время атлета (сек)}} \times 1000$$

* **Зачётные дистанции:** 60м, 100м, 200м, 400м, 800м, 1000м, 1500м, 1 миля, 3000м, 5000м, 10000м (стадион и шоссе), полумарафон (21.1 км), марафон (42.2 км), 100 км.
* **Суточный бег (24 часа):**
  $$\text{Баллы} = \frac{\text{Дистанция атлета (км)}}{\text{Норматив (км)}} \times 1000$$
* **Классификатор дистанций (`parser_running/distance_classification.py`):**
  Нормализация фактических названий дистанций («21,1 км», «Половинка», «Semi-marathon») к каноническим классам с допустимой погрешностью $\pm 2\%$ длины.

### 8.2 Лыжные гонки и биатлон

$$\text{Рейтинг} = \sum \text{Баллы гонок} + (\text{Очки RL за сезон} \times K_{RL})$$
*(где $K_{RL} = 1/7$ по умолчанию).*

* **Баллы за отдельную гонку:**
  $$\text{Баллы} = 100 \times \frac{N_{\text{финишеров пола}} - \text{Место в поле} + 1}{N_{\text{финишеров пола}}}$$
* **Очки серии Russialoppet (RL):**
  $$R = \left(2 - \frac{T_{\text{атлета}}}{T_{\text{лидера группы}}}\right) \times 1000$$

### 8.3 Триатлон

$$\text{Баллы} = \max\left(0, \left(R_{max} \times \left(1 - \frac{T_{\text{атлета}} - T_{\text{лидера}}}{T_{\text{лидера}}}\right) + B_{med}\right) \times K\right)$$
* $R_{max}$: Полная дистанция — 10 000; 113 (половинка) — 5 000; Олимпийка — 2 500; Спринт — 1 250; Суперспринт — 625.
* Бонус за опережение медианы: $B_{med} = 2 \times \max(0, T_{\text{медиана}} - T_{\text{атлета}})$ (в минутах).

### 8.4 Трейл

$$\text{Баллы} = 10 \times \left(\text{Дистанция (км)} + \frac{\text{Набор высоты } D+ \text{ (м)}}{100}\right) \times \left(1 - \frac{T_{\text{атлета}} - T_{\text{лидера}}}{T_{\text{лидера}}}\right)$$

### 8.5 Агрегация и тай-брейки

* Режим **`sum_all`**: сумма всех зачётных стартов за скользящие 365 дней.
* При равенстве баллов места распределяются по правилам:
  1. Более высокий балл за лучший одиночный старт (`best_points`).
  2. Большее количество зачётных стартов (`starts_count`).
  3. Идентификатор атлета (`athlete_id`).

## 9. Руководство по установке, запуску и тестированию

### 9.1 Системные требования

* **ОС:** Windows (PowerShell / WSL), Linux, macOS.
* **Python:** 3.12 или 3.14.
* **Tesseract OCR 5** (только для распознавания биатлонных PDF-протоколов).

### 9.2 Быстрый старт веб-сервиса

```bash
# 1. Клонирование репозитория и переход в каталог
git clone https://github.com/czczczt/sports-agent.git
cd sports-agent

# 2. Создание и активация виртуального окружения
python -m venv .venv
# Для Windows (PowerShell):
.venv\Scripts\Activate.ps1
# Для Linux/macOS:
source .venv/bin/activate

# 3. Установка зависимостей
pip install -r requirements.txt

# 4. Настройка переменных окружения (опционально)
cp env.example .env
# При наличии ключа GigaChat укажите GIGACHAT_CREDENTIALS в .env

# 5. Индексация спортсменов из базы результатов (при первом запуске)
python init_athletes.py

# 6. Запуск веб-сервера с наблюдением за директорией app
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload --reload-dir app
```

После старта веб-сервис доступен по адресам:
* 🌐 **Главная страница (поиск и рейтинги):** [http://localhost:8000/](http://localhost:8000/)
* 🏆 **Таблица лидеров бега:** [http://localhost:8000/rating-view](http://localhost:8000/rating-view)
* 📐 **Формула расчёта и нормативы:** [http://localhost:8000/rating-formula](http://localhost:8000/rating-formula)
* 🛠️ **Панель модерации ИИ-ремонтника:** [http://localhost:8000/agent-review](http://localhost:8000/agent-review)
* 📄 **Документация OpenAPI / Swagger:** [http://localhost:8000/docs](http://localhost:8000/docs)

### 9.3 Запуск парсеров данных

```bash
# Сбор беговых стартов (сохранение в running.db и data/raw/)
python parser_running/run.py --source russiarunning --events 40
python parser_running/run.py --source timerman --events 20
python parser_running/run.py --source runc --events 20
python parser_running/run.py --source grom --events 10

# Дедупликация соревнований и склейка участников
python parser_running/dedup.py

# Автономный синтез парсера для любого URL через GigaChat-2-Pro
python parse_url.py https://probeg.org/race/129181/
```

### 9.4 Запуск набора автоматических тестов

```bash
# Комплексный тест функционала MVP (поиск, UI, API, аналитика)
python test_mvp.py

# Тестирование MCP-агента и валидатора данных
python test_mcp_agent.py

# Тестирование формул расчёта очков и нормативов
python -m unittest tests/test_scoring.py
python -m unittest tests/test_scoring_db.py
python -m unittest tests/test_distance_scoring.py
```
