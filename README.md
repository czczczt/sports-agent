# СберСпорт // Платформа бегового рейтинга (MVP)

MVP веб-платформы и аналитического слоя для сбора результатов соревнований, склейки профилей спортсменов, расчета персональной статистики, визуализации конкуренции и работы ИИ-агентов.

Проект разработан на стеке **Python 3.12+ / 3.14**, **FastAPI**, **SQLite** (`running.db`), **Jinja2**, собственной CSS-темы (светлая/тёмная, адаптив под телефоны) и **Chart.js**.

## ✅ Что было сделано

### 1. Анализ и сохранение целостности базы данных
* Выполнен аудит таблицы `result` в `running.db` (297 225 строк). Подтверждено, что точная дата рождения отсутствует (0%), точный год рождения заполнен лишь у 2.6% (площадка Grom), а у **97.4% участников указан только возраст (`age`)**.
* **Все исходные таблицы парсера (`source`, `event`, `race`, `result`, `issue`, `known_exception`) оставлены на 100% нетронутыми и неизменными.**

### 2. Склейка и материализация сущности спортсмена (Вариант А)
* В исходной БД не было отдельной сущности «спортсмен» — только разрозненные строки протоколов.
* Разработан детерминированный алгоритм склейки ([init_athletes.py](init_athletes.py)), который сгруппировал 297 тыс. записей в **174 051 уникального спортсмена**.
* Созданы вспомогательные таблицы с индексами:
  - `athlete` — карточки спортсменов с агрегированными данными (ФИО, расчетный год рождения, город, клуб, число финишей).
  - `result_athlete` — связь каждого результата `result.id` с профилем `athlete.id`.
  - `athlete_assessment_cache` — таблица кэша персональных отчетов ИИ-агента.

### 3. Поиск спортсмена с выбором кандидата
* Реализован нечувствительный к регистру поиск по фамилии с автоматической заменой букв **е / ё**.
* Реализован расчет года рождения ($\text{год старта} - \text{возраст}$) с допустимой погрешностью **$\pm 1$ год** (компенсирует проведение соревнований до/после дня рождения).
* При обнаружении нескольких совпадений отображается список кандидатов (город, регион, клуб, число стартов), где пользователь выбирает свой профиль.

### 4. Профиль спортсмена и аналитика
* **Таблица завершенных финишей:** фильтрация дубликатов (`duplicate_of IS NULL`) и незавершенных стартов (только статус `FIN`). Отображение старта, даты, дистанции, чистого/пистолетного времени, темпа (мин:сек/км) и мест (абсолютное и по полу).
* **Личные рекорды (PB):** автоматический расчет лучших времен по нормализованным дистанциям (`5000m`, `10000m`, `half_marathon`, `marathon` и др.).
* **Интерактивный график динамики:** визуализация изменения темпа бега спортсмена по времени (Chart.js).
* **Заготовка под рейтинг:** статус `pending_curator_formula` с описанием, подготовленный под внедрение формулы куратора.

### 5. Каталог стартов, дистанции и протоколы
* Каталог соревнований с фильтрацией по дате от/до, городу проведения и площадке (`russiarunning`, `timerman`, `runc`, `grom`).
* Протокол забега с поддержкой поиска по фамилии и стартовому номеру (`bib`).
* **Блок «Конкуренция»:** расчет квантилей (медиана, 25-й процентиль), построение гистограммы распределения финишных времен всех участников забега на 10 интервалов и подсветка положения выбранного атлета в пелотоне.

### 6. ИИ-агент для спортсмена (GigaChat + Локальный движок)
* Бэкенд детерминированно рассчитывает все числовые метрики (процентили, динамику, стабильность темпа $CV$, сильные стороны).
* Агент вызывается только по кнопке. Ответ кэшируется в БД, повторные клики не тратят токены.
* Подключен вызов API GigaChat через переменные в `.env`. Если ключ не задан, автоматически срабатывает встроенный локальный аналитический модуль.
* Выводится обязательный дисклеймер о справочном характере оценки.

### 7. Заготовка под ИИ-агента fallback-парсинга по протоколу MCP
* Разработан модуль валидации качества данных ([validator.py](app/mcp_agent/validator.py)) для обнаружения аномалий (высокая доля `NULL` в ФИО или времени, нарушение монотонности мест).
* Реализован клиент протокола MCP ([mcp_client.py](app/mcp_agent/mcp_client.py)) с контрактами инструментов `playwright_fetch_page` и `llm_extract_table`.
* Реализован оркестратор ([orchestrator.py](app/mcp_agent/orchestrator.py)), автоматически фиксирующий инциденты в таблице `issue` со статусом `agent_working` и запускающий ИИ-парсинг через MCP.

### 8. Черновой демонстрационный веб-интерфейс
* UI на шаблонах Jinja2 и Chart.js в стилистике дизайн-макета «Рейтинг спортсменов» v2: светлая, тёмная и системная темы, мобильная раскладка с нижней навигацией. Решение и соответствие экранов макету — [ADR-0001](docs/adr/0001-frontend-design-system.md).

## 📡 Спецификация REST API

### 1. Спортсмены
* **`GET /athletes/search`**  
  Параметры: `last_name` (строка, обязательно), `birth_year` (число, опционально, допуск $\pm 1$ год), `limit` (по умолч. 50).  
  Возвращает: список кандидатов `AthleteCandidate` (ФИО, расчетный год рождения, город, клуб, число стартов).
* **`GET /athletes/{id}/results`**  
  Возвращает: список всех завершенных результатов спортсмена (чистое/пистолетное время, темп `ММ:СС /км`, места).
* **`GET /athletes/{id}/summary`**  
  Возвращает: сводный профиль, личные рекорды (PB) по дистанциям, массив точек динамики для графика, заготовку рейтинга.
* **`POST /athletes/{id}/assessment`**  
  Вызывает ИИ-агента для формирования персональной оценки. Ответ сохраняется в таблице `athlete_assessment_cache`.

### 2. Старты и дистанции
* **`GET /events`**  
  Параметры: `date_from`, `date_to`, `city`, `source`, `limit`, `offset`.  
  Возвращает: каталог соревнований с перечнем дистанций.
* **`GET /events/{id}`**  
  Возвращает: детальные данные старта и список его дистанций.
* **`GET /races/{id}/results`**  
  Параметры: `search` (поиск по фамилии или номеру `bib`), `limit`, `offset`.  
  Возвращает: финишный протокол дистанции.
* **`GET /races/{id}/competition`**  
  Параметры: `athlete_id` (опционально, для подсветки спортсмена).  
  Возвращает: квантили времени (медиана, 25-й процентиль), 10 интервалов гистограммы распределения и позицию спортсмена.

## 🤖 ИИ-агенты платформы

### 1. Агент персональной оценки спортсмена
* **Принцип разделения ответственности:** все числа считает детерминированный код бэкенда ([analytics_service.py](app/services/analytics_service.py)). Агент получает компактную JSON-сводку и только формулирует текст, не выдумывая факты.
* **Аналитические метрики:**
  - *Соревновательный процентиль:* положение атлета относительно всех финишеров забега:
    $$\text{Percentile} = \frac{N_{\text{участников}} - \text{Place} + 1}{N_{\text{участников}}} \times 100\%$$
  - *Динамика прогресса:* относительное изменение времени первого и крайнего забега на одной дистанции:
    $$\text{Improvement} = \frac{T_{\text{первый}} - T_{\text{крайний}}}{T_{\text{первый}}} \times 100\%$$
  - *Стабильность темпа:* расчет коэффициента вариации темпа $CV = \frac{\sigma}{\mu} \times 100\%$.
* **Провайдеры:**
  - При наличии `GIGACHAT_CREDENTIALS` в `.env` — запрос отправляется в API GigaChat.
  - Если токен не задан — срабатывает встроенный локальный модуль формирования оценки на основе тех же вычисленных метрик.
* **Кэширование:** при повторных кликах текст берется из `athlete_assessment_cache`, исключая лишние запросы.

### 2. Заготовка агента fallback-парсинга по протоколу MCP
* Решает проблему смены разметки на сайтах соревнований или повреждения данных.
* **Конвейер:**
  1. Детерминированный скрипт парсит данные.
  2. Модуль валидации ([validator.py](app/mcp_agent/validator.py)) проверяет процент пустых значений (`NULL`) в ключевых колонках, монотонность времени финишеров и корректность статусов.
  3. При сбое тестов автоматически создается инцидент в таблице `issue` со статусом `agent_working`.
  4. Запускается ИИ-агент по протоколу MCP ([mcp_client.py](app/mcp_agent/mcp_client.py)), который вызывает инструменты `playwright_fetch_page` (headless-браузер) и `llm_extract_table` (извлечение таблицы по JSON-схеме).

## 🚀 Установка и запуск

### 1. Установка зависимостей
Убедитесь, что установлен Python 3.12+ (или 3.14). Выполните установку библиотек:
```bash
pip install -r requirements.txt
```

### 2. Настройка файла переменных окружения (.env)
В корне проекта находится файл `.env`. При необходимости укажите ключ авторизации GigaChat:
```env
SQLITE_DB_PATH=running.db
APP_HOST=0.0.0.0
APP_PORT=8000

# Для подключения GigaChat (необязательно, при отсутствии работает локальный движок)
GIGACHAT_CREDENTIALS=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
GIGACHAT_VERIFY_SSL=false
```

### 3. Индексация спортсменов (однократно)
Если таблица `athlete` пуста, запустите индексацию (занимает ~4 секунды для 297 тыс. записей):
```bash
python init_athletes.py
```
*(При старте FastAPI-приложения проверка выполняется автоматически).*

### 4. Запуск сервера разработки
```bash
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```
После запуска доступны:
* 🌐 **Веб-интерфейс:** [http://localhost:8000/](http://localhost:8000/)
* 📄 **Swagger API:** [http://localhost:8000/docs](http://localhost:8000/docs)
