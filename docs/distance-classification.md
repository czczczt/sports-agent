# Классификация дистанций для баллов (#10)

Классификатор рейтинга находится в `parser_running/distance_classification.py`.
Пересчёт `scoring.recalculate` использует его для каждой строки результата.
Старая `normalize.norm_distance` с допуском ±2% и колонка `race.distance_type`
остаются для парсера и evals: они не заменяются новым классом рейтинга.

## Порядок правил

1. `race.class_source = 'manual'`: использовать `distance_class_override`.
   Значение NULL означает явное снятие зачёта (`manual_exclusion`).
2. Активные регулярные выражения из `distance_synonym`: название дистанции,
   затем название соревнования. Меньшее число `priority` важнее. Несколько
   разных классов с одинаковым приоритетом дают `ambiguous_synonyms`.
3. Метры: ближайшая нормативная длина в пределах ±1% на шоссе; точное
   совпадение на стадионе. Номинальные длины те же, что в нормализации парсера;
   миля представлена целыми 1609 м после округления источника.
4. Нет класса — `unclassified_distance`; причина сохраняется в `score`.

Дисциплина берётся из `race.discipline` (`road` / `track`). Если её нет,
ключевые слова «стадион», «манеж», «дорожка», `track` в названии дистанции
или соревнования означают стадион; иначе шоссе.

Синонимы имеют приоритет над числом метров: в снимке есть названия «5 км»
при длине 4700/5250 м и «10 км» при 10500/10600 м. По правилам #10 они
получают класс из названия, и это видно в расшифровке `classification`.
Ручное назначение позволяет исправить или исключить такие случаи.

Название соревнования используется осторожно: оно не заменяет явную длину
в названии дистанции. Если метры известны, кандидат из названия соревнования
должен согласовываться с ними в пределах 1%. Исключение — суточный формат:
метры могут обозначать длину круга, поэтому «24 часа» в названии соревнования
имеет приоритет для дистанции с общим названием («Участники»). Так детские и короткие забеги
в многодистанционном «Марафоне» не становятся марафонами. Если метров нет,
например «Участники» / «Паркран у озера», допустим класс из названия старта.

## Хранение и администрирование

`db.connect` выполняет идемпотентную миграцию старой схемы. Она добавляет:

- `race.discipline`, `race.class_source`, `race.distance_class_override`;
- `result.distance_km` — **пройденные участником** километры;
- `distance_synonym(pattern, distance_class, priority, enabled)`.

Первый запуск:

```powershell
python parser_running/scoring.py --seed --recalculate --report
```

`--seed` добавляет отсутствующие нормативы и стандартные синонимы. Изменённые
администратором записи не перезаписываются. Чтобы отключить стандартное
правило, установите `enabled=false`; удалённое правило вернётся при новом seed.
Без seed новая таблица правил пуста: пересчёт использует метры и ручные назначения.

Правила можно менять в БД без правки исходников. Например:

```sql
INSERT INTO distance_synonym(pattern, distance_class, priority)
VALUES ('(?i)субботний забег', '5000m', 50)
ON CONFLICT (pattern) DO UPDATE SET distance_class=excluded.distance_class;

UPDATE race SET class_source='manual', distance_class_override='5000m' WHERE id=123;
-- Явно исключить:
UPDATE race SET class_source='manual', distance_class_override=NULL WHERE id=123;
-- Вернуть автоматическую классификацию:
UPDATE race SET class_source='auto', distance_class_override=NULL WHERE id=123;
```

После изменения запустите `--recalculate`; автоматические триггеры и
настройки общего пересчёта относятся к #12. Выражения имеют синтаксис Python
`re`, регистр игнорируется, Ё нормализуется в Е во входных названиях.
Для программного администрирования доступны `set_synonym`, `set_manual_class`,
`clear_manual_class`, `load_synonyms`. Они проверяют входные значения,
работают в транзакции вызывающего кода и сами не делают commit.
`save_race` сохраняет дисциплину источника и не перезаписывает ручной класс.

## Суточный бег

Названия «сутки» и «24 часа» дают класс `24h`. Коннектор должен передать
`row['distance_km']` в `save_results`; это поле не связано с длиной трассы.
`250 / 245 × 1000 = 1020.408163…` для мужчины по нормативу 2026 года.
Без пройденных километров сохраняется `missing_distance`. Время 86400 секунд
не подменяет километры. Существование 24h-поля на конкретной площадке
не предполагается: сквозной импорт проверен синтетическим примером.

## G9 и отчёт «было / стало»

`tests/fixtures/distance_g9.csv` содержит ручную разметку всех 185 уникальных
пар «название + длина» из снимка: 297 дистанций и 297225 результатов.
Для каждой пары записаны ожидаемый класс и пояснение. Метки заданы по ТЗ
после просмотра полного каталога, а не скопированы из выхода классификатора.
Хеш исходной SQLite и происхождение — в `distance_g9_source.json` рядом.
Персональных данных в эталоне и отчёте нет.

```powershell
# PostgreSQL из DATABASE_URL / .env; только чтение, без миграций:
python parser_running/distance_report.py --output distance-report.json
# Старый SQLite-снимок, открывается mode=ro:
python parser_running/distance_report.py --sqlite-snapshot path/to/running.db --output distance-report.json
```

Сравниваются баллы при одинаковых нормативах и правилах допуска: меняется
только классификатор. Выводятся число результатов с баллами и без них,
числа по классам, количество изменившихся начислений, покрытие G9, ошибки
и ошибочно незачётные пары. Новые пары, которых нет в эталоне, показываются
как `unlabelled_pairs`, не считаются автоматически правильными.

Сохранённый отчёт: [distance-classification-report.json](distance-classification-report.json).
На этом снимке G9 — 185/185, покрытие 100%, расхождений и ошибочно незачётных
пар нет. Результатов с баллами: 232916 → 234030 (+1114), из них +443 на 5 км,
+671 на 10 км. Остальные классы не изменились. Это не повторный прогон
актуальной рабочей PostgreSQL: на момент реализации она была недоступна.
G9 подтверждает размеченный снимок; новые названия требуют расширения эталона.

## Проверка

```powershell
$env:SCORING_TEST_DATABASE_URL='postgresql://test_user@127.0.0.1:55439/postgres'
python -m unittest discover -s tests -v
python parser_running/evals/run_evals.py --agent oracle
```

Базовые G1 и новые тесты проверяют баллы, объяснения, приоритеты, G9,
хранение/изменение правил, сохранение ручного класса при импорте,
суточные километры и отсутствие записи баллов при read-only аудите.
Тесты PostgreSQL создают отдельную схему с синтетическими данными и удаляют её.
