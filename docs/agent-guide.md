# Путеводитель разработчика агента сбора данных

Агент Issue #21 генерирует и ремонтирует JSON-рецепты извлечения строк HTML-протоколов. LangGraph управляет попытками и паузой для оператора, Crawl4AI выполняет CSS-схему, а Pydantic проверяет рецепты и строки. PostgreSQL хранит состояние графа, эталоны в виде контрольных сумм и версии рецептов.

## Запуск

1. Установите зависимости из `requirements.txt` и выполните `python -m alembic upgrade head`.
2. Запустите API и воркер `python -m app.worker`. Если API запущен напрямую через Uvicorn на Windows, используйте `--loop app.core.database:postgres_event_loop_factory`.
3. Укажите провайдера в `RECIPE_AGENT_PROVIDER`. Для GigaChat нужны `GIGACHAT_CREDENTIALS` и при необходимости `RECIPE_AGENT_MODEL`. Для Ollama можно задать `RECIPE_AGENT_MODEL` и `RECIPE_AGENT_BASE_URL`. Для vLLM задайте модель и URL с суффиксом `/v1`, а при необходимости `RECIPE_AGENT_API_KEY`.
4. Укажите каталог сохранённых ответов через `RECIPE_RAW_ROOT` или `RECIPE_RAW_HOST_DIR` для Compose. У API и воркера должен быть доступ к одним и тем же файлам. Их путь и SHA-256 берутся из таблицы `raw`.

## Подключение источника и авторемонт

Администратор может отправлять запросы через `/docs` с токеном своей учётной записи.

- `PUT /api/agent-review/recipes/sources/{source_id}/golden` регистрирует 3–5 сохранённых страниц. Для каждой передайте `raw_id`, `place_by` (`chip` или `gun`) и `expected` — массив нормализованных строк `ResultRow` из проверенного источника. Порядок и все канонические значения входят в эталон. Время передаётся в секундах.
- `POST /api/agent-review/recipes` ставит запуск в очередь. Передайте `source_id` и `samples` с 1–3 другими `raw_id`, шкалой `place_by` и при наличии общим числом строк `total`. Для существующего инцидента можно передать `issue_id`.
- В `/agent-review`, в разделе «Рецепты извлечения», подтвердите первый проверенный рецепт, исправьте JSON или отклоните предложение. Ручные правки проходят тот же образец и golden-set. После трёх ремонтов с ошибками решение остаётся за оператором. Прошедшие проверки ремонты активируются автоматически при `AUTO_APPLY_SAFE_REPAIRS=true`.
- `POST /api/agent-review/recipes/{repair_id}/retry` повторно ставит незавершённый запуск в очередь с сохранённой контрольной точкой.
- `POST /api/agent-review/recipes/sources/{source_id}/collect` ставит извлечение в очередь. Воркер берёт последние сохранённые HTML-снимки, связанные с дистанциями без записанных результатов. Для дистанции нужны шкала времени и ожидаемое число строк. После успешной проверки он сохраняет результаты со ссылкой на версию рецепта. При ошибке он открывает один ремонт на источник и возобновляет сбор после его успешного завершения.

Хранение снимков подчиняется общему TTL raw-слоя. Замените golden-set до истечения срока его снимков. Обход соревнований, скачивание новых страниц и извлечение из JSON API или PDF выполняют существующие инструменты проекта. Контур Issue #21 начинает работу с сохранённого HTML.

## Формат рецепта

```json
{
  "baseSelector": "table.protocol tbody tr",
  "fields": [
    {"name": "full_name_raw", "selector": "td.name", "type": "text"},
    {"name": "gender", "selector": "td.gender", "type": "text"},
    {"name": "place_abs", "selector": "td.place", "type": "text"},
    {"name": "gun_time_s", "selector": "td.gun", "type": "text"},
    {"name": "bib", "selector": "td.bib", "type": "attribute", "attribute": "data-number"}
  ]
}
```

Поля рецепта и канонический формат результата определены в [contracts.py](../app/recipe_agent/contracts.py). Извлечение и golden-set выполняются локально по снимкам. Вызовы модели происходят на этапах генерации и ремонта.

## Проверка

```bash
python -m pytest tests/test_recipe_agent.py tests/test_procrastinate_worker.py
```

Для интеграционного теста задайте `TEST_POSTGRES_ADMIN_URL` на отдельном тестовом сервере с правом создавать временные базы. Тест использует сохранённые HTML и подменяет провайдер модели.
