## 1. Концепция: почему декларативные рецепты вместо генерации кода

В старой архитектуре предполагалась генерация агентом произвольного Python-кода (патчи файлов коннекторов через поиск и замену строк, создание веток `git worktree` и Pull Request). Это создавало критические риски:
1. **Безопасность:** запуск недоверенного исполняемого Python-кода в контуре сервиса, возможность инъекций через вёрстку страниц соревнований.
2. **Нестабильность:** патчи строк ломались при малейшем сдвиге контекста в репозитории (`patch_conflict`).
3. **Расход токенов:** неэффективно тратить миллионы токенов на сканирование каждой страницы результатов.

### Ключевой принцип новой архитектуры:
> **LLM — не парсер и не генератор Python-кода, а автор и ремонтник декларативных JSON-рецептов.**

- **Рецепт** — это структурированные декларативные данные: CSS-схема селекторов для библиотеки `Crawl4AI` (`JsonCssExtractionStrategy`) или маппинг полей открытого JSON API.
- **0 токенов на регулярный сбор:** основной конвейер сбора сотен тысяч строк протоколов исполняется детерминированно библиотекой `Crawl4AI` / `httpx` на полной скорости без обращения к нейросети.
- **LLM привлекается только один раз** при добавлении площадки или при изменении её вёрстки для починки селекторов.
- **Никаких правок файлов `.py`:** агент возвращает только JSON со схемой извлечения. Рецепты версионируются в базе данных (`recipe`, `recipe_version`).

## 2. Классы источников

| Класс | Примеры площадок | Формат рецепта | Роль LLM |
|---|---|---|---|
| **A. Открытый JSON API** | RussiaRunning / Timerman, myrunstats | `ApiRecipe`: URL эндпоинта + JSON-путь к строкам + маппинг полей в `ResultRow` | Создание и правка маппинга полей (1–3 тыс. токенов) |
| **B. HTML или JSON в HTML** | results.runc.run, grom.place, probeg.org, results.zone | CSS-схема Crawl4AI (`baseSelector`, `fields` с типами `text`, `attribute`, `regex`) | Генерация CSS-селекторов и их ремонт при поломке |
| **C. Неструктурированные сканы / PDF** | Редкие биатлонные протоколы | Docling / OCR-слой + схема нормализации таблицы | Вне первой версии (ручная загрузка в MVP) |

## 3. Место агента в конвейере данных

```
Регулярный сбор (worker) ──► Crawl4AI (0 токенов) ──► Валидация ResultRow
                                                             │
                                        упала проверка       ▼
                                                     таблица issue (kind = 'parse_failed' | 'zero_rows')
                                                             │
                                                             ▼
                                                    Агент-ремонтник (LangGraph / Pydantic AI)
                                                             │
                                                             ├─ Вход: старый рецепт + HTML-образец + ошибки
                                                             ├─ Песочница: прогон Crawl4AI с новым рецептом
                                                             ├─ Проверка: Golden-set регрессия не ухудшилась?
                                                             │
                                        ┌────────────────────┴────────────────────┐
                                        ▼                                         ▼
                            golden-set пройден:                         golden-set не пройден (3 попытки):
                       новая версия recipe_version                  эскалация человеку в админку (/agent-review)
```

1. **Изоляция сбоев:** падение одной площадки генерирует запись в таблице `issue`. Остальные адаптеры продолжают сбор в штатном режиме.
2. **Один ремонт на площадку за раз:** пока агент чинит рецепт для источника, остальные страницы этого источника ставятся на паузу, предотвращая лавину дублирующих задач.
3. **Безотказность:** старая версия рецепта сохраняется в БД. При необходимости администратор может откатить активную версию в один клик.

## 4. Архитектура агента: конечный автомат (StateGraph)

Логика агента организуется в виде детерминированного конечного автомата (LangGraph / Pydantic AI):

```
       [generate_recipe] ◄──────┐ (до 3 итераций при ошибках)
               │                │
               ▼                │
       [execute_sandbox]        │
               │                │
               ▼                │
       [validate_output] ───────┘ fail (ремонт селекторов)
               │
               ├─ ok (golden-set пройден) ──► [save_recipe_version]
               │
               └─ исчерпаны попытки ───────► [human_review] (эскалация администратору)
```

### Узлы графа:
1. **`generate_recipe`:** LLM анализирует 1–3 сохранённых HTML-образца соревнований и генерирует черновик CSS-схемы для Crawl4AI (`baseSelector` строки таблицы и селекторы ячеек: ФИО, время, нагрудный номер, клуб, город, категория).
2. **`execute_sandbox`:** тестовый прогон сгенерированного рецепта в песочнице без сети с использованием `JsonCssExtractionStrategy`.
3. **`validate_output`:** проверка извлечённых данных эвристиками и контрактом Pydantic:
   - Извлечено $> 0$ строк;
   - Время валидно парсится в миллисекунды (форматы `ЧЧ:ММ:СС`, `ММ:СС,д`);
   - Поля ФИО содержат кириллические символы и разделены на Фамилию и Имя;
   - Число строк с заполненным местом коррелирует с общим числом строк.
4. **`diagnose_repair`:** при ошибках валидации формируется контекст ошибки (`ModelRetry`), и модель точечно корректирует селекторы.
5. **`save_recipe_version` / `human_review`:** успешная схема сохраняется как новая версия рецепта в `recipe_version`. При невозможности починить за 3 попытки задача передаётся человеку в веб-интерфейс подтверждения.

## 5. Контракт агента

### 5.1 Входные данные (`Task`):
- `source_code`: идентификатор источника (например, `runc`, `results_zone`);
- `recipe_id`: текущий рецепт из БД (если ремонт) или `null` (если подключение нового источника);
- `samples`: список путей к 1–3 сохранённым HTML-файлам в песочнице;
- `validation_errors`: лог ошибок валидации (проваленные проверки контракта `ResultRow`);
- `golden_set`: сохранённые эталонные результаты для проверки регрессии.

### 5.2 Выходные данные (`RecipeProposal`):
```json
{
  "status": "success",
  "recipe_type": "crawl4ai_css",
  "schema": {
    "name": "protocol_table",
    "baseSelector": "table.results-table tbody tr.participant-row",
    "fields": [
      {"name": "place", "selector": "td.col-place", "type": "text"},
      {"name": "bib", "selector": "td.col-bib", "type": "text"},
      {"name": "full_name", "selector": "td.col-name a", "type": "text"},
      {"name": "birth_year", "selector": "td.col-year", "type": "text"},
      {"name": "club", "selector": "td.col-club", "type": "text"},
      {"name": "gun_time", "selector": "td.col-time", "type": "text"},
      {"name": "chip_time", "selector": "td.col-chip-time", "type": "text"}
    ]
  },
  "explanation": "Сайт обновил вёрстку: селектор строк таблицы изменён с tr.row на tr.participant-row. Поле клуба перенесено в 5-ю колонку.",
  "tokens_used": 1850
}
```

Если проблема не связана с вёрсткой (например, 403 Cloudflare, таймаут или капча):
```json
{
  "status": "escalate",
  "reason": "Площадка вернула HTTP 403 (Cloudflare защита). Требуется настройка прокси или переход на браузерный сбор worker-browser.",
  "escalate_to": "infra"
}
```

## 6. Безопасность

1. **Никакого выполнения Python-кода:** агент возвращает исключительно JSON-схему селекторов. Никаких `exec()`, `eval()`, генерации `.py` файлов или шелл-скриптов.
2. **Строгая Pydantic-валидация:** JSON-рецепт валидируется строгой схемой перед загрузкой в движок парсинга.
3. **Защита от промпт-инъекций:** сырой текст из HTML-страниц протоколов подаётся модели как неисполняемые данные (в экранированных блоках контекста). Любые системные инструкции, внедрённые в имена участников или названия клубов, игнорируются.
4. **Бюджет токенов:** лимит на задачу ремонта — не более 3 итераций и не более 15 000 суммарных токенов. При превышении лимита задача эскалируется человеку.

## 7. Критерии приёмки и валидация (Golden-Set)

1. **0 регрессий:** новый рецепт не должен ухудшать результаты на сохранённых образцах `golden-set`.
2. **Точность полей:** 100% совпадение ключевых полей (чистое время, место) на эталонных протоколах.
3. **0 галлюцинаций:** значения времени и дистанций извлекаются строго селекторами из DOM, модель не «додумывает» цифры.
4. **Устойчивость к шуму:** заголовки таблиц, баннеры и пустые строки автоматически отфильтровываются схемой.
