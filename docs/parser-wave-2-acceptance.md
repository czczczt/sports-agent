## Повторный импорт и защита данных

### TopList, проверка [#33](https://github.com/czczczt/sports-agent/issues/33) от 26 ноября 2026 года

Оба прямых чтения публичного API вернули одинаковые ID результатов в том же порядке. Для 7,5 км (ID `31210`) страницы со смещениями 0, 50, 100 и 150 дали 199 уникальных FIN, а запрос со смещением 199 вернул пустую страницу с `total=199`. Для 15 км (ID `31211`) страницы со смещениями 0, 50 и 100 дали 127 уникальных FIN, а запрос со смещением 127 вернул пустую страницу с `total=127`. Счётчики дистанций и общий счётчик события (326) совпали с выгрузкой. [Событие в API](https://toplist.run/api/race/10227) · [API 7,5 км](https://toplist.run/api/competition/10227/31210?from=199&length=50&sort=position) · [API 15 км](https://toplist.run/api/competition/10227/31211?from=127&length=50&sort=position)

На стр. 5–8 PDF организатора 199 FIN и 1 DNF (номер 406). В выгрузке TopList на этой дистанции номера 406 нет. На стр. 14–16 PDF 127 FIN и 0 DNF. Времена лидеров, D+ и справочные очки TopList совпали с контрольными значениями выше. Публичная страница протокола использует тот же API результатов. Альтернативной полной выгрузки на странице не найдено, а запрос отсечек для 7,5 км вернул пустой список. [Публичный протокол TopList](https://toplist.run/race/10227/protocol/31210) · [API отсечек](https://toplist.run/api/competition/10227/checkpoints/31210) · [PDF организатора](https://probeg.org/dj_media/uploads/2025/250706_Pr_Kross-treyl__Nabor_v_Novosibirsk_5943.pdf)

Два живых импорта через API и воркер в отдельную PostgreSQL сохранили те же 326 FIN, ID всех строк, контрольные времена, D+ и справочные очки. Версия рейтинга не публиковалась. Офлайн-сценарий с опубликованным DNF подтвердил его добавление через воркер и сохранение ID всех строк при повторном импорте.

Для приёмки #33 согласована публичная выгрузка TopList. Для старта `10227` достаточно её охвата в 326 FIN. DNF № 406 опубликован в PDF организатора и отсутствует в данных TopList.

### Прогоны второй волны

Повторы TopList (8) и TriStats (9) сохранили идентификаторы результатов, счётчики, проверяемые поля и набор связей. Повтор Results.zone (10) завершился сетевым таймаутом. Все 1 290 строк, их идентификаторы, контрольные значения и набор связей сохранились. Успешный повтор Results.zone проверен офлайн. Диагностические отказы RaceTime, MyFinish и Orgeo не записали протоколы и не создали версию рейтинга.

При повторном импорте официальных файлов Orgeo сохранились все 215 идентификаторов и контрольные значения. В интеграционном тесте неполный Live-ответ после успешного импорта оставил сохранённые строки без изменений. Публикация версии рейтинга пропущена, поскольку PDF содержит только официальное время.

При архивном старте за пределами 365-дневного окна публикация текущего рейтинга пропускается. Если ранее учтённый старт переместился за границу окна из-за исправления даты, пересчёт выполняется. Интеграционный тест на фикстурах проверяет включительность 365-го дня, архивный 366-й день, повтор после публикации с сохранением связи и протокола, а также пересчёт при исправлении даты. Сценарии с опубликованным рейтингом и отказами проверяются офлайн.

Для повторения стендовой проверки администратор отправляет POST на `/api/v1/runs` с `kind=collect`, кодом источника и `event_code` из таблицы. GET на `/api/v1/runs/{run_id}` показывает статус, число обработанных дистанций, ошибку и версию рейтинга. Полученные дистанции сверяются через `/api/races/{race_id}/results` и агрегаты в изолированной PostgreSQL.

## Задачи для снятия блокеров

- **TriStats.** На стенде с исходящим IP в РФ найти финальный протокол, сверить дату и охват статусов и повторить импорт. Если площадка отдаёт только финишёров, требуется решение владельца ТЗ по допустимому охвату.
- **RaceTime.** Подтвердить финальность и полноту по официальному протоколу, устранить расхождение на 1 км и успешно провести запуск через воркер.
- **MyFinish.** Получить доступный итоговый протокол или официальный файл организатора и подтвердить его импорт.

Статус ручной приёмки выставляется после сквозной проверки [#31](https://github.com/czczczt/sports-agent/issues/31).
