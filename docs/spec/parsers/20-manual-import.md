# Ручная загрузка — внутренние старты Сбера, TopSki и неподключённые площадки

## Проблема

Часть протоколов доступна только файлом или через площадку, для которой ещё нет адаптера.

## Решение

Добавить управляемый импорт файлов через общий конвейер с предварительной проверкой.

## Пользовательские истории

1. Как администратор, я хочу загрузить файл, проверить предпросмотр и увидеть итог импорта, чтобы обрабатывать старты без отдельных скриптов.
2. Как модератор, я хочу видеть источник и неоднозначные совпадения, чтобы подтверждать только корректные привязки.
3. Как пользователь рейтинга, я хочу видеть согласованные результаты, чтобы сбой источника не менял мой балл.
4. Как разработчик, я хочу воспроизвести разбор на сохранённом образце, чтобы проверять изменения без сети.

## Решения по реализации

- Реализовать последовательность файл → старт и дистанция → сопоставление колонок → предпросмотр → подтверждение → отчёт. Сопоставление и импорт проверяют права администратора или капитана своего вида.
- Поддержать внутренние старты Сбера, TopSki и резервный путь для Pioner Cup. Не включать подразделение в маппинг. Ограничивать объём загрузки и применять TTL ко временному сырью.
- Предпросмотр показывает ошибки, число строк и возможные дубли. После подтверждения применять общие проверки, запись и публикацию по правилам дисциплины.
- Применять общий контракт источников и постановку в очередь из спеки «ПроБЕГ — второй источник и общий конвейер». Проверять данные до записи, сохранять происхождение и предыдущие корректные результаты при ошибке.
- По мере готовности расчёта дисциплины публиковать согласованную версию рейтинга. Для дисциплин без рабочего расчёта отражать факт импорта отдельно от публикации, без подмены бегового рейтинга.

## Тестирование и приёмка

- [ ] Файлы внутреннего и внешнего старта, повторная загрузка, неверный маппинг и чужой вид капитана. До подтверждения данные сайта не меняются.
- [ ] Сквозной сценарий через API и воркер на временной PostgreSQL. Используется обезличенный тестовый файл. Проверить повторный импорт и сохранение опубликованных данных при ошибке по образцу пилота #27.
- [ ] Перед включением импорта сверить один реальный обезличенный протокол на отдельном стенде с официальным протоколом. Проверить дистанции, число строк и контрольные значения. CI работает офлайн.
