# ADR-0002. Веб-интерфейс на React (SPA) вместо Jinja-шаблонов

- Статус: принято
- Дата: 2026-11-13
- Дополняет: [ADR-0001](0001-frontend-design-system.md) — дизайн-система и токены не меняются, меняется только способ рендеринга.

## Контекст

Интерфейс рендерился на сервере: Jinja-шаблоны `app/templates/*.html`, общие макросы `_ui.html` и скрипты прямо в шаблонах (Chart.js, Air Datepicker, поле года рождения, ИИ-оценка, правки агента). Логика страниц частично жила в HTML-маршрутах `app/main.py` (строка «это вы» в рейтинге, закреплённый результат в протоколе, нормативы формулы), поэтому получить те же данные через API было нельзя.

Дальше в интерфейс будут добавляться новые экраны и интерактив, а на шаблонах со встроенным JS это растёт плохо: нет компонентов, типов и общей загрузки данных.

## Решение

1. **Отдельное приложение `frontend/`** — React 18 + TypeScript + Vite 5, маршрутизация React Router 6. Chart.js 4.4.1 и Air Datepicker 3.5.3 подключены как npm-пакеты тех же версий, что раньше шли с CDN.
2. **Бэкенд отдаёт только JSON.** Все запросы интерфейса идут на `/api/...`. Логика из HTML-маршрутов перенесена в сервисы и новые эндпоинты:
   - `GET /api/rating` — рейтинг и строка `me_row` (с пересчётом места внутри пола), `rating_service.get_rating_me_row`;
   - `GET /api/rating/formula` — нормативы года, `rating_service.get_rating_norms`;
   - `GET /api/races/{id}` — страница дистанции целиком (протокол, закреплённый результат при месте > 100, «Конкуренция», топ по рейтингу), `events_service.get_race_page`;
   - `GET /api/agent-review/page` — экран правок агента; роутер агента переехал с `/agent-review/api/...` на `/api/agent-review/...`.
   Старые адреса без префикса (`/athletes`, `/events`, `/races`) оставлены для совместимости и скрыты из Swagger.
3. **URL страниц не изменились** (`/`, `/athletes-view/{id}`, `/rating-view`, `/rating-formula`, `/events-view`, `/events-view/{id}`, `/races-view/{id}`, `/agent-review`) — старые ссылки и закладки работают. Фильтры и поиск по-прежнему живут в query-параметрах.
4. **Раздача.** `app/frontend.py` монтирует `frontend/dist/assets` и для всех прочих GET отдаёт `index.html` (SPA-fallback), кроме `/api/...` и `/docs` — там честная 404. Если сборки нет, сервер отвечает 503 с инструкцией, как собрать. В разработке Vite (порт 5173) проксирует `/api` на uvicorn (порт 8000).
5. **Дизайн перенесён без изменений.** `theme.css` переехал в `frontend/src/styles/theme.css` как есть; стили, которые были в `<style>` внутри шаблонов, — в `frontend/src/styles/app.css`. Разметка и классы страниц повторяют шаблоны. Макросы `_ui.html` → `src/lib/format.ts` (форматирование) и `src/components/ui/` (иконки, бейджи, пустые состояния), `theme.js` → `src/theme/ThemeProvider.tsx`.
6. **Jinja удалена:** `app/templates/`, `app/static/` и зависимость `jinja2`.

## Как проверяли, что вёрстка не поплыла

Старая версия (ветка `main`) и новая запускались рядом на одной базе. На каждой странице — при ширине 1280, 768 и 375 px — снимались координаты и размеры всех видимых элементов шапки, контента, подвала и нижней панели и сравнивались поэлементно. Итог: совпадение до пикселя, кроме перечисленного ниже.

## Отличия от прежнего интерфейса (намеренные)

- **Quirks-режим.** Профиль и рейтинг раньше рендерились в quirks-режиме (в шаблонах `<style>` стоял перед `<!DOCTYPE>`). В нём таблицы не наследуют `line-height`/размер шрифта, а высота строк округляется. React работает в стандартном режиме, поэтому эти особенности повторены явно (`.table--legacy-metrics`, `.rating-table` в `app.css`) — таблицы выглядят как раньше. Иконка темы в мобильной шапке на этих двух страницах теперь стоит так же, как на остальных (раньше была на 3 px выше).
- **Календарь дат.** Оформление Air Datepicker под тему в `theme.css` раньше не применялось: CSS библиотеки подключался позже и перебивал его (календарь был белым с голубым выделением даже в тёмной теме). Теперь работает задуманное оформление — цвета темы, зелёное выделение, шрифт Golos Text.
- **Нижняя панель на телефоне** была свёрстана на 2 колонки при 3 пунктах — «Найти себя» уезжал на вторую строку за край экрана. Теперь колонок столько, сколько пунктов.
- **Карточки поиска на 320 px** вылезали за экран из-за длинного имени; теперь имя обрезается многоточием.
- **«Как посчитано»:** «100k м» → «100 км»; в навигации подсвечивается «Рейтинг», а не «Найти себя».
- **Загрузка данных** идёт после открытия страницы, поэтому на долю секунды виден индикатор загрузки. Неизвестный адрес или несуществующий id показывают «не найдено» внутри обычного каркаса сайта.
- **Правки агента:** подключение к PostgreSQL парсера ограничено 5 секундами (`connect_timeout`) — без базы экран сразу показывает сообщение, а не висит минуту.

## Изменения дизайна после переноса

- **Рейтинг:** убран пьедестал топ-3 — он дублировал первые строки таблицы, где места 1–3 уже отмечены медалями. Стили `.rating-podium*` удалены из `theme.css`.
- **Выбор дистанции на странице дистанции** (`components/ui/DistancePills.tsx`). Раньше пилюли стояли в одну строку с системной полосой прокрутки. Теперь на компьютере и планшете они переносятся на новые строки — видно все дистанции без прокрутки. На телефоне (до 760 px) — одна лента на всю ширину экрана, листается пальцем; полоса прокрутки скрыта, у края, за которым есть ещё дистанции, пилюли затухают (подсказка, что можно листать), выбранная дистанция при открытии прокручивается в видимую часть.

## Последствия

- Для запуска сайта нужен Node.js 18+ и сборка: `npm --prefix frontend install && npm --prefix frontend run build`. Без неё API работает, а страницы отвечают 503 с подсказкой.
- Новая страница: компонент в `frontend/src/pages/`, маршрут в `src/routes.tsx`, запрос в `src/api/endpoints.ts`, типы ответа в `src/api/types.ts` (повторяют pydantic-модели из `app/models.py`), пункт меню — в `src/config/navigation.ts`. Подробно — `frontend/README.md`.
- Правила ADR-0001 действуют: только классы `theme.css` и токены цветов, иначе сломается тёмная тема.
- При изменении pydantic-модели нужно обновить `frontend/src/api/types.ts` — `npm run build` (там же `tsc`) покажет, где типы разошлись.
