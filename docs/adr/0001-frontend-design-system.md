# ADR-0001. Дизайн веб-интерфейса по макету «Рейтинг спортсменов» v2

- Статус: принято
- Дата: 2026-10-29

## Контекст

Черновой интерфейс (`app/templates/*.html`) был собран на Tailwind CDN «для проверки бэкенда»: без тёмной темы, с эмодзи вместо иконок и без мобильной навигации. Дизайн-макет лежит в Claude Design: https://claude.ai/artifact/9KSM9dk719Ri1cScr3srK7, страница **v2** («Публичная часть»: `Pub0x_*` — телефон, `PubD0x_*` — десктоп, у каждого экрана светлая и тёмная версия).

В макете больше экранов, чем в проекте (рейтинг, «Как посчитано», «Поделиться», «Сообщить об ошибке», кабинеты капитана и админа). Их **не добавляем** — переделываем только существующие страницы.

## Решение

1. **Своя тема вместо Tailwind.** Стили в `app/static/css/theme.css`, токены цветов перенесены из макета один к одному (`--bg-base`, `--surface`, `--brand-*`, `--sport-run*`, `--medal-*`, `--status-*` и т. д.). Tailwind CDN удалён.
2. **Шрифты:** Unbounded 600/700 для заголовков и крупных чисел, Golos Text 400/500/600 для текста (Google Fonts).
3. **Темы:** светлая, тёмная и «Системная» (по умолчанию, через `prefers-color-scheme`). Выбор хранится в `localStorage['theme']` и выставляется атрибутом `html[data-theme]` инлайн-скриптом в `<head>`, до отрисовки. Логика переключения — `app/static/js/theme.js`; графики Chart.js читают цвета из токенов (`window.themeToken`) и перерисовываются по событию `themechange`.
4. **Адаптивность:** до 760 px — мобильная раскладка из макета: компактная шапка с кнопкой темы, нижняя панель навигации, таблицы заменены списками строк (`.only-desktop` / `.only-mobile`), формы в одну колонку. На десктопе — верхняя навигация с подчёркиванием активного раздела и переключатель темы из трёх вариантов.
5. **Общие макросы** — `app/templates/_ui.html`: inline SVG-иконки в стиле макета, форматирование дат/времени, склонения, бейджи статусов (FIN / DNF / DSQ).

## Соответствие страниц проекта экранам макета

| Страница проекта | URL | Экран макета |
|---|---|---|
| Поиск спортсмена | `/` | 2 · «Найти себя» (`Pub02` / `PubD02`) |
| Профиль спортсмена | `/athletes-view/{id}` | 3 · «Карточка спортсмена» (`Pub03` / `PubD03`) |
| Каталог стартов | `/events-view` | 6 · «Старты» (`Pub06` / `PubD06`) |
| Карточка старта | `/events-view/{id}` | нет в макете — собрана из шапки экрана 5 и списков экрана 6 |
| Дистанция и протокол | `/races-view/{id}` | 5 · «Карточка старта» (`Pub05` / `PubD05`) + блок «Конкуренция» |

## Отступления от макета

- Раздела «Рейтинг» в проекте нет, поэтому в навигации только «Старты» и «Найти себя»; на месте «Вход для капитанов» — ссылка на Swagger.
- В проекте один вид спорта (бег), поэтому плитки «Лыжи/Бег» на профиле заменены плитками «Бег · финишей» и «Рекорды»; место в рейтинге показано заглушкой «на согласовании», пока нет формулы (`docs/scoring-spec.md`).
- Вместо графика «Место по месяцам» — график темпа по стартам (рейтинговых мест в данных пока нет).
- Блоки «ИИ-оценка» и «Конкуренция» (гистограмма) в макете отсутствуют — оформлены карточками в общей стилистике.
- Кнопки «Поделиться», «Сообщить об ошибке», «Это не мой результат» не перенесены: за ними нет экранов и API.

## Последствия

- Новые страницы строятся из классов `theme.css` (`.card`, `.btn`, `.chip`, `.table`, `.list-row`, `.tile` …) и макросов `_ui.html`; цвета — только через токены, иначе сломается тёмная тема.
- Если в проект добавятся экраны из макета (рейтинг, «Как посчитано» и т. п.), их брать с той же страницы v2.
